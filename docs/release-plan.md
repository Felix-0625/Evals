# 开源发布计划

发布目标为 GitHub 仓库和 Release，应用保持本机单可信操作者运行。

按以下顺序推进，每项保留检查结果、修复范围和复验依据。

1. 完成真实模型使用验收。使用临时 DeepSeek 凭证、VeraAgent 临时沙箱和 NexRAG 公开生成资料。记录实际工具、答案、业务状态、费用和失败结果。
2. 扫描应用代码、继承组件和依赖。验证可触达的问题，优先修复高风险漏洞及崩溃边界。
3. 清理前端失效代码。以入口、引用和构建结果为依据保留原 Viewer 功能。
4. 核对字体和组件许可证。检查实际分发文件、商用许可、归属声明和未使用字体。
5. 核对后端路由。区分页面、CLI、外部 API 及组件内部调用，删除已有证据确认失效的入口。
6. 整理代码维护规范。统一自有代码注释为英文，文档和产品界面使用中文。补充关键约束和失败语义，拆分职责混杂的大模块，保留已验证的公共接口。
7. 检查冗余逻辑和实现问题。优先沿用组件能力，用最小修复解决已复现缺陷，复杂问题核对上游文档和成熟实现。
8. 整理仓库、示例和文档。明确自有代码与继承组件，排除临时产物和凭证，单列评测与 RSI 的流程、权限和证据条件。
9. 执行发布检查。完成回归、前端构建、浏览器使用、干净检出安装、依赖审计和许可证清单。
10. 提交并推送清晰的提交批次。核对远程仓库内容和对应提交的 CI，发布版本标签、Release 说明和已验证的发行物。

真实模型验收只能支持其实际样本范围。长期稳定性、生产负载和持续收益根据后续证据更新。
